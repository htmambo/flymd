# 打开文件外部更改监听 — 使用指南

> 适用版本:flymd v0.x(PR-1 + PR-1.1 + PR-2 之后)
> 英文版:见 [`EXTERNAL_FILE_WATCH_GUIDE.en.md`](./EXTERNAL_FILE_WATCH_GUIDE.en.md)

## 概述

flymd 在打开文件时会**自动监听**该文件的外部修改。其它程序(编辑器、IDE、网盘同步、git pull 钩子等)对文件写入时,flymd 会按"当前标签是否被修改过"做不同处理,确保你既不丢本地编辑,也不漏掉外部更新。

> 一期范围:仅监控**当前激活标签**对应文件;后台标签的外部修改会被忽略,以避免误覆盖未展示的编辑。

## 行为策略

| 当前标签状态 | 检测到外部修改时 |
|---|---|
| **干净**(无未保存改动) | 自动用磁盘内容覆盖,并显示 toast "文件已在外部更新,已自动重新加载" |
| **脏**(有未保存改动) | 弹三选一模态,让你决定怎么处理 |
| **文件被删除 / 不可访问** | 提示"文件已被删除或无法访问,标签已转草稿",标签自动脱离文件路径 |

### 脏标签模态的三个选项

1. **取消**:暂不动作,保持本地编辑;之后保存会覆盖外部版本
2. **保留本地(下次保存覆盖)**:不动作,但 watcher 内的快照已对齐;之后再触发需要等到磁盘真的变了
3. **重新加载(放弃本地)**:丢弃本地编辑,加载磁盘最新内容

> 焦点默认在"取消"按钮,防止误操作。`ESC` 或点击遮罩同样视为取消。

## 偏好设置

**入口**:`文件` 菜单 → `文件监听设置…`

三个开关:

| 开关 | 默认 | 关闭后效果 |
|---|---|---|
| **启用外部修改监听** | ✅ 开 | 外部修改不会触发任何提示或自动重载(策略层 + 核心层都停) |
| **干净标签自动重载** | ✅ 开 | 干净标签也不再自动重载,只显示提示;后续仍由你手动决定 |
| **调试日志** | ❌ 关 | 打开后,watcher 与 integration 的详细日志会输出到控制台(便于排查) |

偏好会持久化到 `flymd-settings.json` 中的 `externalFileWatch` 字段:

```json
{
  "externalFileWatch": {
    "enabled": true,
    "autoReloadClean": true,
    "debugLog": false
  }
}
```

> 切换"启用外部修改监听"会立即生效:关闭时 watcher 释放所有监听句柄;重新开启时会重建监听。

## 范围与限制

1. **仅激活标签**:后台标签的外部修改**不**会触发提示(避免误覆盖未展示的编辑)。切换到该标签时会做一次 stat 复检,若有差异会走完整策略。
2. **PDF 文件不监听**:PDF 由内置 reader 自管理(`isSkippablePath` 规则匹配 `.pdf` 扩展名)。
3. **网盘同步客户端**(iCloud / OneDrive / Dropbox):
   - 同步**完成**后的最终写入可被检测到
   - 同步**过程中**的中间态(rename + write)有两级 stat 重试(400ms)兜底
   - 仍可能偶发"双触发",但第二次因快照未变会被丢弃
4. **大文件**:目前只比 mtime + size(≤ 1MB 的可选 hash 计划在 PR-3 实现,本期未启用)
5. **保存后**:`saveFile` / `saveAs` 前后有 2 秒抑制窗口 + snapshot 刷新,自写入事件不会被误识别为外部修改
6. **关闭偏好总开关**:完全停止监听(策略层 + 核心层);偏好切换不要求重启应用

## 故障排查

### Q1: 外部修改文件后,flymd 没任何反应

按顺序检查:

1. **总开关是否关闭**?`文件` → `文件监听设置…` → 确认"启用外部修改监听"打开
2. **被修改的文件是不是当前激活标签对应文件**?后台标签的修改会被忽略
3. **被修改的文件是不是 PDF**?PDF 不监听
4. **打开"调试日志"开关**,在控制台看是否有 `[openFileWatcher]` 相关日志:
   - 无日志 → 监听未启动,可能浏览器/降级环境,或 watchPathsAbs 失败
   - 有日志但无 `[modified]` 事件 → 文件路径不匹配(可能路径规范化差异)
   - 有 `[modified]` 但 `[suppress]` 提示 → 命中了 2s 抑制窗口(可能是自写入回环)

### Q2: 自动重载后,内容没变化或被误标为已修改

1. 检查"干净标签自动重载"是否打开
2. 打开"调试日志",查看 `[openFileWatcher] event handler` / `[openFileWatcher] checkChange` 日志
3. 如果在**所见(WYSIWYG)模式**遇到,确认 YAML Front Matter 是否被保留(已知修复于 PR-1.1,commit 371997b)

### Q3: 切回后台标签后,内容没更新

后台标签事件会被忽略;切回时**会自动做一次 stat 复检**。如果复检未触发:
- 该标签可能没有 filePath(草稿标签)
- watchPathsAbs 在该父目录监听失败(查"调试日志")

### Q4: 保存文件后,被识别为外部修改并弹提示

这是 PR-1 已修复的**自循环回环**。如果仍出现:
- 打开"调试日志",应看到 `[openFileWatcher] 抑制自循环事件`
- 如未看到 → 抑制窗口没起作用,可能是 watchPathsAbs 在 2s 内没派发到
- 已知边界:保存后 2s 内的**第三方**修改仍会被抑制(预期行为,防写入竞争)

## 实现细节(给开发者)

```
┌─────────────────────┐    ┌──────────────────────────────┐
│ src/core/           │    │ src/core/                    │
│ openFileWatcher.ts  │    │ openFileWatcherIntegration.ts│
│ (核心层)            │    │ (策略层)                     │
│                     │    │                              │
│ - watchPathsAbs     │◀───│ - deps.enabled (偏好注入)    │
│ - 2s 抑制窗口       │    │ - dirty=false:自动重载       │
│ - 二级 stat 重试     │    │ - dirty=true:弹模态          │
│ - snapshot 精确比对  │    │ - 文件删除:转草稿            │
└─────────────────────┘    └──────────────────────────────┘
                                    ▲
                                    │ deps 注入
                                    │
                          ┌─────────────────────┐
                          │ src/main.ts         │
                          │ - 装配集成层         │
                          │ - showFileWatch     │
                          │   ConflictDialog    │
                          │ - showFileWatch     │
                          │   PrefsDialog       │
                          └─────────────────────┘
```

- 核心层 **不**依赖 UI / 业务,可在浏览器/单测环境降级为 no-op
- 策略层 **不**依赖核心层内部,只通过 `OpenFileWatcher` 接口
- main.ts 是**唯一**装配点,负责把所有依赖(mainStore / NotificationManager / i18n)注入
